过了半年再打开自己写的脚本，最先遇到的问题往往不是代码，而是“它当时到底怎么运行的？”

## 把约定放在看得见的地方

输入文件放在哪里、需要什么版本的运行时、结果写到哪里——这些信息应该和代码住在一起。

一个短小的 README，通常比一段记忆更可靠。

## 失败也应该有形状

文件不存在时给出文件名，参数错误时解释期待的格式。不要把所有问题都折叠成一句“出错了”。

```text
input → validate → transform → output
           ↓
      explain the error
```

## 保留简单的出口

如果工具的输出是一份普通文本，它就能被其他工具读取，也能被未来的自己理解。可组合性有时来自这样很小的选择。
